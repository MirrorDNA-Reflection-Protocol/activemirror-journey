# Active Mirror Plan

## Now

1. Keep the homepage chat-first and simple.
2. Keep privacy nudges warm and placeholder-based.
3. Keep artifacts as actual outputs, not instructions.
4. Keep model/provider names out of consumer copy.
5. Keep source-sensitive turns marked before reliance.

## Next Product Slice

1. Make the first screen even clearer:
   - primary: `Start Reflection`;
   - secondary: `Already have settings?`;
   - tertiary: `For teams`.
2. Keep BrainScan/MirrorSeed as a short setup, not a lecture.
3. Add one elegant generated surface only when useful:
   - draft;
   - document;
   - code starter;
   - visual brief.
4. Add a small "use placeholders" privacy helper that never feels like a scolding block.

## Next Control-Plane Slice

1. Add a lightweight context-pack builder only after the static guard proves useful.
2. Add an approval request template for risky deploy/file/memory actions.
3. Add a small report command that prints checked scope, unchecked scope, and bad news.

## Do Not Do Yet

- Do not expose kernel internals on the consumer homepage.
- Do not claim model training, LoRA, or owned local model sync until implemented and verified.
- Do not position the product as a medical, therapy, or psychiatric tool.
- Do not mix SWFI/client language into the public Active Mirror flow.
