The Model Is Interchangeable

Every AI company wants you to believe their model is the product. It isn't. The model is a commodity. Identity lives in the bus.

The lock-in you don't notice

Every major AI provider is running the same play: make you dependent on their model. Your chat history lives in their cloud. Your context, your preferences, your conversation style — all tied to one API endpoint. Switch providers and you start from zero.

This isn't accidental. It's the moat. The model itself is getting commoditized — GPT-4 quality is available from a dozen providers now. So the lock-in shifts to data. To context. To continuity.

I built my stack to resist this from day one.

The core thesis: The model is a replaceable component. Identity — your state, your context, your history — lives in data structures you own. Build it that way, and no provider can hold you hostage.

What "interchangeable" actually means

My system runs Claude, Gemini, Groq, DeepSeek, and eleven local Ollama models. They all share one thing: a session protocol. Every session starts by reading a continuity file — a structured document containing my current state, recent decisions, open loops, and context.

The model doesn't hold the context. The file does. When Claude hits rate limits, Gemini reads the same file and picks up the thread. When I'm offline, a local Ollama model handles low-risk tasks using the same context. The experience is continuous because the protocol is continuous.

# Session start — any model reads this
Read the approved continuity packet
# Output: Paul's state, what happened, what's next

# Session end — any model writes this
session commit "What was accomplished"
# Output: bus updated, handoff generated, next model can continue

The sovereignty test

Here's the test I use: if I deleted every API key right now, what would survive?

The answer: everything that matters. My vault — 5,000 notes. My session history. My continuity file. My decision log. My self-critique record. My shipped inventory. All of it lives on disk, in files I own, in formats I can read without any vendor.

The models are rented compute. The identity is mine.

How access is controlled

Not every model needs access to everything. A low-risk task handled by a local model doesn't need my full memory — just the current context. I use OAuth-style scoping: each model gets a token that defines what it can read and write.

This is standard software engineering applied to AI: least privilege, scoped access, revocable tokens. The fact that nobody talks about this for AI systems is the gap I'm trying to close.

What to build toward

If you're building with AI seriously, here's the principle I'd start with: design for model deprecation. Assume the model you use today will be gone or inferior in 18 months. GPT-4 Turbo, Claude 2, Gemini Ultra — they've all been superseded. The next ones will be too.

The infrastructure that survives that churn is the infrastructure worth building. Session protocols. Structured memory. Continuity files. Governance layers. These don't need to change when the model changes.

Build systems where identity lives in data structures, not in model weights.

The model is interchangeable. The bus is identity. That's the architecture worth owning.
