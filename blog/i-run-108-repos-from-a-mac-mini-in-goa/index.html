I Run 108 Repos from a Mac Mini in Goa

108 GitHub repos. 49 ports listening. 91 LaunchAgents. 15 local AI models. All running on a single Mac Mini M4 with 24GB RAM — in a 4,000-person fishing village with spotty electricity and wonky internet.

108 GitHub repos (54 public, 54 private)
49 Ports actively listening
91 LaunchAgent services
15 Local Ollama models
24GB RAM, Mac Mini M4
5K+ Notes in knowledge vault

Why one machine

I moved to a small fishing village in Goa with a clear constraint: one machine, no office, no team. The Mac Mini M4 with 24GB unified memory became the entire production stack — not a dev environment, the actual production stack.

No Kubernetes. No cloud VMs. No "scale to zero" serverless functions that introduce cold-start latency and vendor dependency. One box. Everything runs on it.

The constraint forced decisions that turned out to be correct: lightweight services, process supervision instead of containers, local AI models instead of API calls for everything, a memory bus on the filesystem instead of a managed database.

What's actually running

The 49 ports aren't all big services. Some are tiny — a 200-line Python FastAPI that does one thing. Others are heavier: the MirrorGate governance stack, the semantic cache router, the scam detection API. But they all run on the same box.

The 91 LaunchAgents keep everything alive. Not systemd — LaunchAgents, the macOS native process supervisor. They restart services on crash, run scheduled jobs, feed the memory bus every 60 seconds, and watch for anomalies in service health.

Local models for local work

Fifteen Ollama models live on disk. The smallest is 352MB (qwen2:0.5b for fast classification). The largest is 8.9GB (deepseek-coder-v2:16b for heavy code tasks). Total model storage: ~50GB.

The routing logic is simple: if a task is low-risk and low-complexity, it goes to a local model. No API cost. No latency. No data leaving the machine. Claude handles the complex reasoning. Local models handle the volume.

I also fine-tuned one model specifically for governance verification — mirrorgate:v1, a LoRA adapter on Qwen2.5-7B. It checks whether agent actions comply with standing policies before they execute. The fine-tune runs in 200 iterations on 288KB of training data.

The electricity and internet problem

Goa has power cuts. The internet is a 4G hotspot from a phone most days. This forced genuine resilience — not "we have fallbacks" resilience, but "the system has to keep running when the network disappears for 30 minutes" resilience.

The local AI models mean core functionality survives a network outage. The filesystem-based memory bus means no database connection to lose. The LaunchAgents mean services restart automatically when power returns. None of this was clever design — it was necessity.

Constraints that seem like disadvantages are often the most honest teacher. The fishing village forced an architecture that's more resilient than what you'd build in an office with reliable infrastructure.

What this proves

The conventional wisdom is that serious AI infrastructure requires cloud scale — managed databases, distributed compute, Kubernetes orchestration, SRE teams. This stack is evidence that's false.

108 repos. 49 services. 15 local models. Multi-agent orchestration with governance. Self-healing infrastructure. A scam detection product serving real users in India. A publishing pipeline synthesizing from a 5,000-note knowledge vault. All on one Mac Mini. In a village.

The Mac Mini M4 with 24GB unified memory is genuinely capable of running a sovereign AI stack at this scale. The Apple Silicon memory architecture means models share memory efficiently with the rest of the system. It's not a compromise — it's the right hardware for this use case.

You don't need a data center. You need good architecture and the discipline to keep it simple.

Paul Desai is the founder of Active Mirror and Chetana — a free scam detection platform for India. Built solo in Goa. Running on one Mac Mini. Reflections at beacon.activemirror.ai.
